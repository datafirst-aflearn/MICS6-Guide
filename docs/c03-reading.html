3.3 Constructing research-ready reading variables

The raw MICS6 reading data are unusually difficult to use correctly across countries.

AFLEARN’s reading-processing script addresses four problems:

  1. multiple reading passages and languages;
  2. passage length, which is needed to calculate the 90% accuracy threshold;
  3. country-specific variable layouts and questionnaire adaptations; and
  4. complex skip patterns, which mean that a missing passage result can have several substantively different explanations.

The goal is to turn the raw reading fields into variables that researchers can interpret without reconstructing the questionnaire routing every time.

3.3.1 The script

The current AFLEARN script is harmonize-mics-reading-v1.1.R. It reads Data/UNICEF/ and writes to Data/AFLEARN Harmonised Data/.

run-it.R already sources this script after the FS harmonisation. To re-run only the reading construction, from the project directory:

source("Script/harmonize-mics-reading-v1.1.R")

The implementation writes:

Data/AFLEARN Harmonised Data/mics6-reading-harmonised.dta
Data/AFLEARN Harmonised Data/mics6-reading-harmonised.rds

with one child-level record per fs observation in the supported surveys and identifiers that allow the reading variables to be merged with the harmonised fs data or an IPUMS MICS extract.

3.3.2 Why AFLEARN constructs additional reading variables

3.3.2.1 Problem 1: a country can have more than one passage

In multilingual surveys, the original UNICEF file can contain more than one reading passage. Malawi is the clearest example: children could be assessed in English and Chichewa.

A research-ready dataset therefore needs to know which passage the child attempted, what language that passage was, and how long it was.

This is also why the IPUMS reading variables should not be used in multi-passage MICS6 countries: as explained in Getting data from IPUMS MICS, IPUMS retains only one passage in these cases.

3.3.2.2 Problem 2: passage length is required for reading accuracy

MICS foundational reading requires at least 90% of the passage words to be read correctly.

If words attempted = A and words read incorrectly = I, then words read correctly = A − I. That is not enough to determine accuracy. We also need L, the total number of words in the passage, so that

\[ \text{reading accuracy} = \frac{\text{words read correctly}} {\text{passage length}} \]

The released country datasets do not provide one simple harmonised variable giving the length of the passage administered to each child. AFLEARN therefore constructs passage_language and passage_length.

3.3.2.3 Problem 3: missing reading results have different meanings

Consider these children:

Child A   age 6
Child B   age 10, caregiver did not consent
Child C   age 10, no suitable assessment language
Child D   age 10, child declined the story
Child E   age 10, failed the practice sequence
Child F   age 10, attempted the main passage

A simple reading-score variable may be missing for A–E. These children did not reach the same point in the assessment and should not be treated as a single “missing reading data” category. AFLEARN therefore creates reading_status.

3.3.3 The reading_status variable

The current harmonisation distinguishes:

Code Reading assessment status
0 Not interviewed
1 Outside the FLS reading age range
2 Caregiver consent not given
3 Child consent not given
4 Assessment language mismatch
5 Child did not want to read the story
6 Failed the practice sentence/questions
7 Attempted a reading passage
8 Met the foundational-reading criterion
9 Not classified because the data are inconsistent with the expected routing

This variable serves two purposes. It makes sample construction transparent: researchers can see why an age-eligible child has no passage score. It also makes data-quality checks easier. Code 9 identifies observations that cannot be reconciled with the expected questionnaire pathway rather than silently forcing them into another category.

Do not recode all non-attempts as children who cannot read

A child who was not assessed because an appropriate language was unavailable has not demonstrated the same thing as a child who attempted the passage and read no words correctly.

3.3.4 Reading outcomes in the harmonised file

The current output includes:

Variable Meaning
passage_language Language of the main/primary passage
passage_length Number of words in that passage
words_att Words attempted
words_incorrect Words missed/read incorrectly
reading_score Words read correctly
reading_accuracy Share of passage words read correctly
read_comp_1–read_comp_5 Five comprehension items
read_comp_score Number of comprehension items correct
reading_skills Foundational-reading classification
reading_status Assessment pathway/outcome
*B* variables Corresponding fields for a second passage where applicable
max_reading_* Best result across passages where more than one was attempted

The output also retains:

country_iso3
year
HH1
HH2
LN
cluster
hhno
linech

so that it can be merged to both AFLEARN’s harmonised fs file and an IPUMS child extract.

3.3.5 Children who attempted more than one passage

Some children attempted more than one reading passage. This is analytically different from a child who attempted only one.

The AFLEARN processing retains passage-specific information and creates max_reading_* variables so that researchers can identify the best observed result across passages where this is appropriate for the research question.

State explicitly how multiple attempts are handled rather than silently choosing one.

3.3.6 Checking the output

In R:

library(haven)
library(dplyr)

reading <- read_dta(
  "Data/AFLEARN Harmonised Data/mics6-reading-harmonised.dta"
)

reading %>%
  count(country_iso3, year)

reading %>%
  count(country_iso3, reading_status)

summary(reading$reading_accuracy)

Reading accuracy should normally fall between 0 and 1. Values outside that range should trigger investigation.

Inspect the distribution of passage languages:

reading %>%
  count(country_iso3, passage_language)

and, for multi-passage countries, passage-specific attempt counts.

3.3.7 Merge reading onto the harmonised fs file

In R:

library(dplyr)

fs <- haven::read_dta(
  "Data/AFLEARN Harmonised Data/mics6-fs-harmonised.dta"
)
reading <- haven::read_dta(
  "Data/AFLEARN Harmonised Data/mics6-reading-harmonised.dta"
)

analysis <- fs %>%
  left_join(
    reading,
    by = c(
      "country_iso3",
      "year",
      "HH1",
      "HH2",
      "LN"
    ),
    relationship = "one-to-one",
    suffix = c("", "_reading")
  )

Before merging, check that the keys are unique in both files.

fs %>%
  count(country_iso3, year, HH1, HH2, LN) %>%
  filter(n > 1)

reading %>%
  count(country_iso3, year, HH1, HH2, LN) %>%
  filter(n > 1)

In Stata:

use "Data/AFLEARN Harmonised Data/mics6-fs-harmonised.dta", clear

isid country_iso3 year HH1 HH2 LN

merge 1:1 country_iso3 year HH1 HH2 LN using ///
    "Data/AFLEARN Harmonised Data/mics6-reading-harmonised.dta"

tab _merge

3.3.8 Implementing the 90% accuracy threshold

AFLEARN implements the reading-accuracy threshold using the passage-specific word count and reproduces the classification used in MICS publications.

Where 90% of the passage length is not an integer, AFLEARN uses the integer cutoff that reproduces the published MICS classification. This choice was validated empirically by comparing alternative classifications against published MICS results.

The detailed validation and construction rules are documented in Reading-variable construction.

You now have the core pieces required for UNICEF-based analysis: a harmonised fs file plus research-ready reading data.
